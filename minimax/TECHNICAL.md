# 一页技术说明

**目标。** 围绕可运行的订单列表工程，给 AI 开发助手提供当前任务所需规格、代码、测试及持久化进度，完成一次可核对的代码修改。模块入口是 `python -m sdd`，任务输入为 `sample/task.json`。

**数据与选择。** `store.py` 读取工程中的真实 `.md`、`.py` 文档，记录相对路径、类别、全文和 SHA-256，通过 `pylibseekdb` 启动真实嵌入式 seekdb，使用 PyMySQL 写入 `sdd_documents`。导入在事务中替换快照，更新规格与删除文件都反映到后续检索。任务 query 分词后通过绑定参数的 `INSTR` SQL 选择命中行，分别收集规格、代码、测试，每类最多 4 条。上下文正文直接来自查询返回行，包含可核对路径、行区间和哈希；必要来源缺失则拒绝构造上下文。

**状态与恢复。** `state.py` 打开固定版本的 PowerContext Builtin Runtime，通过 Scope 和 Memory 的 `remember/get` 保存和读取完成事项、待办、验证结果。状态内容由 PowerContext SQLite 后端管理，地址文件仅保存 Scope 和精确 Memory citation。独立命令关闭运行时后，新命令重新打开数据库并通过相同引用读取。`context.py` 使用恢复的待办生成 `next_action`，并把验证结果加入模型上下文，任务恢复产生实际后续用途。

**模型开发。** `model.py` 复用明确指定的 Claude 配置或 MiniMax 环境变量，通过官方 HTTPS Anthropic 兼容接口发送一次包含检索证据和任务状态的请求。解析最终 JSON 代码响应，校验目标路径、输入源码哈希及 Python 语法，生成补丁并替换目标源文件。本次响应 id 为 `0732aa1bee32833fa3cefb67c407383c`，返回模型 `MiniMax-M3.1-Flash`。鉴权头及私有思维链不进入交付物。

**验证与追溯。** `verify.py` 在全新目录运行真实服务，各 CLI 操作在独立 OS 进程执行。修改前目标测试 4 个、12 次功能断言失败，回归测试 3 个通过；MiniMax 修改后同一测试文件中的 7 个测试全部通过。日志记录命令、退出码和源代码/测试 SHA-256，另验证重启状态复用及规格 v2 重导入。交付含前后快照、统一差异、模型开发记录、SQL 查询记录、PowerContext 地址和读取证据。评审可无需模型凭据重用已记录的代码结果，再实际执行数据库、状态及所有测试。

**边界。** 各运行目录单工程、单写者；采用确定性子串检索，适用于本次局部开发样例，未宣称向量语义搜索或全仓库排名。PowerContext 管任务状态，seekdb 管工程证据，MiniMax 管业务代码生成，各项技术均在同一任务链路中实际使用。
